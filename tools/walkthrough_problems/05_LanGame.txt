langame/common/protocol.py::Message.to_wire
Turn a message into bytes ready to send: one JSON object {"type", "payload"} followed by a newline, encoded as UTF-8. Keep Hebrew readable (ensure_ascii=False).

langame/common/protocol.py::Message.from_wire
Turn one received line back into a Message. Invalid JSON, a missing or unknown type, or a payload that is not a dict raises ProtocolError - never a raw json or KeyError. The server must survive garbage from any client.

langame/common/protocol.py::MessageBuffer.feed
TCP is a stream: two messages can arrive glued together, or one can arrive in two pieces. Add the new bytes to what is pending, cut at every newline, return the complete messages and keep the unfinished end for next time. Anything longer than the size limit raises ProtocolError.

run_server.py::print_local_addresses
Print every IPv4 address of this computer (and 127.0.0.1) so players know what to type in their client.

langame/server/game_server.py::GameServer.serve_forever
Open a TCP socket on the port (reusable after a restart), listen, and accept connections in a loop. Give each new connection its own ClientHandler thread and keep it in the handler list. A one-second timeout lets the loop notice a shutdown.

langame/server/game_server.py::GameServer.broadcast
Send a message to every player who joined. Copy the handler list under the lock, then send outside it, so one slow client cannot block the others. A handler whose send fails is reported to the engine as left.

langame/server/game_server.py::GameServer.remove_handler
Remove a finished handler from the list (under the lock).

langame/server/game_server.py::GameServer.shutdown
Stop the accept loop, save a game that is in progress, close every client and the listening socket.

langame/server/client_handler.py::ClientHandler.run
The thread of one client: receive bytes, cut them into messages and dispatch each one. A garbage message gets an ERROR reply and the thread keeps serving; a closed connection ends the loop and always closes the handler.

langame/server/client_handler.py::ClientHandler._dispatch
Turn a message into a Command and let the engine execute it. A bad payload gets an ERROR reply. The handler never decides game rules itself.

langame/server/client_handler.py::ClientHandler.send
Send a message to this client under its send lock (two threads may send at once). On a network error return False instead of raising - the caller may be broadcasting to everyone.

langame/server/client_handler.py::ClientHandler.close
Close the handler once (calling it again does nothing): tell the engine the player left, close the socket and remove the handler from the server.

langame/server/commands.py::JoinCommand.execute
Accept a new player only in the lobby, with a name of 1-16 characters that is not taken, while there is room. Otherwise return an ERROR with a code like "name_taken", "game_started" or "full".

langame/server/commands.py::LeaveCommand.execute
Tell the engine this player left.

langame/server/commands.py::build_command
Turn a message into the matching Command (JOIN, ANSWER, LEAVE, START_GAME). Missing or wrongly typed fields raise ProtocolError("bad_payload"); any other type raises ProtocolError("unexpected_type").

langame/server/game_engine.py::GameEngine.execute
Run a command under the engine lock and send its ERROR reply (if any) back to that client. Log every command.

langame/server/game_engine.py::GameEngine.add_player
Add the player, remember its handler, make the first player the host, send it WELCOME and send everyone the updated lobby.

langame/server/game_engine.py::GameEngine.player_left
A player disconnected: in the lobby remove them (and choose a new host if needed) and update the lobby; during a game keep their score, and close the question early if everyone still here has answered. Never crash.

langame/server/game_engine.py::GameEngine.lobby_payload
The lobby message: the names of the connected players and the minimum needed.

langame/server/game_engine.py::GameEngine.connected_players
The players who are still connected.

langame/database/db.py::Database.get_connection
Open an SQLite connection usable from any thread, with dict-like rows and foreign keys switched on. Each call opens its own short connection.

langame/database/db.py::Database.connection
A context manager: commit on success, roll back on an error, always close.

langame/database/db.py::Database.initialize_schema
Create the tables by running the SCHEMA script.

langame/database/repositories.py::QuestionRepository.add
Insert a question (text, four options, the correct index, category, difficulty) and return its id.

langame/database/repositories.py::QuestionRepository.get
Read one question by id with its four options as a list, or None.

langame/database/repositories.py::QuestionRepository.list_ids

langame/database/repositories.py::QuestionRepository.count
How many questions there are, optionally in one category.

langame/database/repositories.py::QuestionRepository.import_csv
Import questions from a CSV in one transaction and return how many were added. Rows with a correct index outside 0-3 (or other broken values) are skipped and reported.

langame/common/models.py::Question.public_payload
What goes into a QUESTION message: id, text and options - never the correct index, or a modified client could cheat.

langame/server/question_manager.py::QuestionManager.prepare
Take all matching question ids, shuffle them and keep `count` for this game. Too few questions raises a clear ValueError before the game starts.

langame/server/question_manager.py::QuestionManager.next
Take the next prepared id and return its question.

langame/server/score_engine.py::ScoreEngine.points_for
Points for one answer: a wrong answer gets 0; a correct one gets 1000 x (time left / time limit), at least 100. Answering in 3 of 15 seconds gives 800. Keep the time between 0 and the limit.

langame/server/score_engine.py::ScoreEngine.score_round
Mark every answer correct or not, give it its points and add them to the player's score. Players who did not answer get nothing.

langame/common/models.py::build_leaderboard
Sort the players by score (highest first, then by name) and number them from 1. Players who left stay on the board.

langame/server/commands.py::StartGameCommand.execute
Only the host may start, only in the lobby, and only with enough players. Not enough questions becomes an ERROR too.

langame/server/commands.py::AnswerCommand.execute
Pass the answer to the engine, which checks it.

langame/server/game_engine.py::GameEngine.start_game
Prepare the questions, reset the scores, leave the lobby (no more joining), tell everyone the countdown and schedule the first question.

langame/server/game_engine.py::GameEngine.next_question
After the last question end the game. Otherwise take the next question, clear the answers, broadcast it (without the answer, with the time limit and number) and start the timer that closes it.

langame/server/game_engine.py::GameEngine.record_answer
The key check of the game. Refuse an answer when no question is open, for an old question, with a choice outside 0-3, or a second time from the same player. Otherwise store it with the server's own timing; when everyone has answered, close the question early.

langame/server/game_engine.py::GameEngine.close_question
Close the question once (the timer and the last answer may both call it): score the answers, keep them for the database, broadcast the result and the leaderboard, and schedule the next question.

langame/server/game_engine.py::GameEngine.result_payload
The result message: the question id, the correct index and each player's answer {choice, is_correct, points}, keyed by name.

langame/server/game_engine.py::GameEngine.leaderboard_payload
The leaderboard message: the ranked entries as dicts.

langame/client/network_client.py::NetworkClient.connect

langame/client/network_client.py::NetworkClient._reader_loop
